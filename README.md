# Valley Word Quest — Daily Dash (v1.0)

A fully client-side, mobile-friendly daily word-guessing game for grades **3–12**, designed for a school learning hub.

## Install on GitHub Pages

1. Create a public GitHub repository, such as `valley-word-quest`.
2. Upload `index.html`, `styles.css`, `game.js`, and `word-bank.js` **to the same directory**.
3. Enable **Settings > Pages > Deploy from branch > main / (root)**.
4. The game will be at `https://YOUR-USERNAME.github.io/valley-word-quest/`.
5. Add that URL to your Learning Hub's game tile. The files also work offline by opening `index.html` locally.

No npm, build server, API keys or third-party accounts are needed. The visual style uses CSS and system font fallbacks; optional Google Fonts load only with an internet connection.

## Rules and features

- **One puzzle per date, per grade.** Grades 3–4 get 4 letters, 5–6 get 5, 7–8 get 6, 9–10 get 7, and 11–12 get 8.
- **Same grade + same local calendar date = same answer** on any device using this version, provided their clocks/dates agree. New calendar-year shuffles keep answers from repeating within a year. Holiday-specific answers are reserved so they don't appear on ordinary dates.
- **Word banks:** 5,709 grade-assigned answers (3,589 unique words) and 85,462 allowed spelling entries across lengths 4–8. Each grade has at least 392 eligible year-round answers plus the seasonal overrides. Answers are selected from high-frequency dictionary entries, with a school-oriented exclusion list. Important: word suitability and difficulty should still be reviewed by a teacher for the intended age group; corpus frequency is not a formal readability rating.
- **Daily attempt limits:** 7 (grades 3–4), 6 (grades 5–8), 7 (grades 9–12). No retry after finishing a date's puzzle.
- **Streaks** require consecutive calendar days with wins. A loss breaks the streak. Grade-specific wins, best time, win rate, achievement badges and shareable results are stored per local nickname.
- **Timer** starts with the first typed letter and pauses if the page is hidden. The timer is restored on reload. Optional one-time first-letter hint adds 30 seconds.
- Calendar shows previously finished puzzles and outcome, but does not let players replay earlier days or open future puzzles.
- New themes cover spring, summer, autumn, winter, plus special events: Halloween, harvest/Thanksgiving, Jan 1, Feb 14, Pi Day, Earth Day, summer solstice, back-to-school, winter solstice.
- Sound is **off by default** for classrooms. Reduced motion and high-contrast tiles are available.

## Privacy and limitations

- No personal information is transmitted by the game. Nickname and puzzle history are stored **only in this browser using `localStorage`**. Profiles are not password-protected; other people using this same browser can switch nicknames. For schools, **use non-identifying nicknames rather than full student names**.
- Data **does not sync across devices or browsers** and can be cleared by browser settings; private/incognito mode may not preserve progress.
- The clock is read from the device. There is **no server-side anti-cheating or cross-device enforcement** of a once-daily rule. If you later need centralized classroom leaderboards, school-account sync, or server-enforced daily puzzles, those require an approved backend and authentication design.
- Calendar results are historical summaries, not replayable archives.

## Source and word bank customization

`word-bank.js` is generated by `build_words.py` using frequency data from TextBlob `en-spelling.txt` (based on public-domain Gutenberg books plus word-frequency sources) and its `en-lexicon.txt` (Brill-tagged lexicon and later additions). Guess validation also uses entries from the CMU Pronouncing Dictionary. TextBlob corpus and lexicon notices: https://textblob.readthedocs.io/ ; CMUdict: https://github.com/cmusphinx/cmudict . The generated files are bundled directly for offline play. Review license and attribution before redistribution beyond the classroom.

To regenerate the word-bank files locally, Python needs `textblob` and `cmudict`; the **game itself** does not require them. To adapt vocabulary, edit `build_words.py` or manually change the grade arrays in `word-bank.js`. Holiday answer pools are at `window.VWQ_WORDS.holidays`.

The date algorithm in `game.js` is deterministic and versioned; **avoid changing answer lists after students begin a school year**, because doing so can change earlier answers for the same grade/date. For a future bank expansion, implement a versioned algorithm or stable year-specific answer schedules.

## Files

- `index.html` — game layout, dialogs, calendar, accessible controls.
- `styles.css` — responsive visual theme, tile and achievement animations.
- `game.js` — deterministic daily word, Wordle-style feedback including repeated letters, persistent results, streaks, local profile, themes and timer.
- `word-bank.js` — bundled answer and guess dictionary; no network fetch.
- `build_words.py` — optional source for regenerating dictionary with installed Python dependencies.
